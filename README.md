# Data reliability platform

A four-year project-based learning programme that grows into a launch-ready data reliability and insight product.

**Current deliverable:** roadmap, subject coaching library, progress records, microservices architecture and release acceptance criteria. The production platform is a planned outcome. No service is currently deployed, and no launch gate has been passed.

The demonstration follows a retailer with orders in CSV, inventory in a database, and support tickets behind an API. The product finds broken feeds and inconsistent records, runs recoverable workflows, and provides traceable reports, forecasts and evidence-backed explanations.

## What is included

- 16 three-month terms, 64 product work packages, prerequisite gates and workload limits.
- A subject learning map, a coached first month, and a runnable day-one Python component.
- Separate progress states for understanding a concept, delivering a product feature and operating a release.
- Service ownership, API/event contracts, customer connector boundaries, multi-tenant security, recovery, evaluation and release requirements.
- The local project folder also retains 404 inherited coaching cards and original Word, PDF and Excel companions. Those inherited materials are excluded from this public repository. The new packages and launch gates are tracked separately and are not silently added to the original workbook.

## Project decisions

Python is the primary self-study language. Java is college-led with independent project checks. FastAPI follows Python fundamentals. C and C++ use bounded parsing and processing labs inside this product. Go and Rust get narrowly justified roles. No IoT track is included. UI sketches begin early; React implementation comes in terms 14–15. AI/ML is introduced after the maths and programming gates.

The target system uses microservices with explicit data ownership. A beginner first learns a small component, then runs two communicating services, and gradually expands the system. Every deployed service must meet the production requirements; creating service folders does not demonstrate readiness.
