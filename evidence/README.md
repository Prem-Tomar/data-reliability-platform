# Evidence folders

Create dated subfolders for term demonstrations, contract tests, recovery drills, benchmarks, security reviews, ML evaluations and release rehearsals. Keep synthetic examples in Git. Exclude customer data, credentials, tokens and raw production logs.

For every experiment record the commit and artifact digest, dependency versions, environment, input fixture version, exact procedure, expected result, observed result, limitations and reviewer/date.

For a launch gate also record the release candidate, owner, evidence links, review date and decision. A successful older release does not automatically approve a changed release.
